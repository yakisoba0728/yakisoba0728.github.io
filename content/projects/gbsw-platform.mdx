## 한 줄 소개
경북소프트웨어마이스터고등학교의 상벌점·학적·계정·출입증·커뮤니티를 한곳에서 다루는 자체 호스팅 웹 서비스입니다.

## 아키텍처
3계층 구조로 책임을 나눴습니다.

- **Route / Server Action** — 세션 확인(`requireAuth`)과 zod 입력 검증
- **Service** — 권한 판정(`can()`), 업무 로직, 감사로그 기록(`recordAudit()`)
- **Repository** — Prisma 호출만 담당

공통 기능(`core`: 인증·권한·감사·DB)과 14개 업무 모듈(상벌점, 출입증, 커뮤니티, 학적, 초대, 감사로그, 인증번호 등)로 나뉩니다.

## 동작 흐름 1 — 상벌점 부여
1. 교사가 로그인 세션을 통과합니다.
2. 반 명단에서 학생 여러 명과 규정을 고릅니다.
3. 입력을 경계에서 zod로 검증합니다.
4. 서비스 계층이 권한을 다시 판정합니다.
5. 트랜잭션으로 기록하고 감사로그를 남깁니다.
6. 학생과 학부모가 본인 점수를 조회합니다.

## 동작 흐름 2 — 외출·외박증
1. 학생이 신청합니다.
2. 외박이면 보호자가 동의합니다.
3. 교사가 승인하거나 반려합니다.
4. 정문에서 학생증 QR을 스캔해 확인합니다. QR은 HMAC 서명을 하고 20초 단위로 갱신되어 캡처한 화면을 재사용할 수 없습니다.

## 핵심 기능
- 규정 114개 기반 상벌점(교내·기숙사 트랙 분리 집계), 취소 사유 필수, 통계·확인서 인쇄·엑셀 내보내기
- 엑셀 명단 업로드(미리보기 → 확정 2단계)로 학년도·반 편성 교체
- 초대 기반 가입, 학부모 초대 코드, 이메일·휴대폰 인증
- 최초 관리자 계정은 서버 콘솔에만 출력되는 1회용 토큰으로 생성
- 권한 거부까지 기록하는 감사로그, 첨부파일(EXIF 처리)이 있는 커뮤니티

## 기술적 포인트
- **다층 방어**: 화면에서 막아도 서비스 계층에서 권한을 다시 검사하고, 세션으로 알 수 있는 식별자는 클라이언트 입력으로 받지 않음
- **DB 제약**: "현재 학년도는 하나뿐" 같은 규칙을 부분 유니크 인덱스로 보장
- **테스트 3층**: 단위(mock), 실제 PostgreSQL 통합, Playwright E2E. 테스트 파일 200여 개
- **CI·배포**: 단위·통합 검증 job, standalone 빌드에 환경 파일·소스가 섞이지 않았는지 검사, Docker Compose(DB → 마이그레이션 → 앱) 배포

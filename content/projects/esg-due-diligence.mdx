## 한 줄 소개
그룹사 법인들이 공급망 ESG 실사 문항에 답하고 증빙을 첨부하면, 시스템이 증빙 후보를 추천하고 ESG 담당 부서가 검토·승인하는 업무 시스템입니다. 실제 기업 환경에 배포해 운영하고 있습니다.

## 아키텍처
- **데이터 준비** — Python 도구가 체크시트(xlsx)와 증빙 폴더를 파싱해 시드 데이터를 만들고, API의 시드 단계가 PostgreSQL에 반영합니다. 흐름이 한 방향이라 스키마는 Prisma만 소유합니다.
- **API** — NestJS: 인증, 제출, 증빙 라이브러리, 추천, 검토, 협력사 실사, 일정·알림
- **비동기 작업** — 업로드 후처리(본문 색인, 문서 유형 분류, OCR)와 추천 갱신을 DB 기반 작업 큐로 처리
- **웹** — Next.js
- **운영** — Docker Compose(db·api·web), 매일 백업과 롤백용 이미지 보관

## 동작 흐름 — 실사 응답부터 승인까지
1. ESG 담당 부서가 초대 코드를 발급하고 법인 담당자가 가입합니다.
2. 담당자가 증빙을 올리면 해시로 중복을 거르고, 색인·유형 분류(정책·활동·성과·인증)·OCR이 비동기로 돌아갑니다.
3. 문항의 선택지마다 추천된 문서·페이지를 보고 근거를 연결해 답변을 저장합니다. 다른 사람이 먼저 수정했다면 충돌로 거부해 덮어쓰기를 막습니다.
4. 검토를 요청하면 규칙 기반 1차 판정(O/△/X)이 실행됩니다.
5. ESG 담당 부서가 확정하거나 보완을 요청합니다. 1차 판정과 다르게 결정하려면 사유를 반드시 남겨야 합니다.
6. 보완과 재검토를 반복하며, 모든 기록은 지우지 않고 덧붙이기만 합니다.

## 핵심 기능
- 법인 × 평가 회차 단위 제출과 소속 조직 기반 권한
- 증빙 라이브러리: 파일 버전, 유효기간, 보관, 본사 피드백
- 파일명·본문 색인 기반 증빙 추천과 정확도 측정 스크립트
- 문항 단위 검토 상태 기계, 1차 협력사 실사(요청·답변·판정·개선)
- 모의평가, 일정·알림, 평가연도 복사, 체크시트 변경 비교·반영

## 기술적 포인트
- **인증·보안**: httpOnly 쿠키 JWT, 기본 거부 전역 가드, 로그인 rate limit, 로그인 CSRF 방어, 탭 간 계정 전환 감지
- **데이터 무결성**: advisory lock을 건 단일 트랜잭션 시드, 운영 환경에서 초기화 거부
- **테스트**: API 단위 테스트 파일 200여 개, 웹 70여 개, E2E 시나리오 50여 개
- **CI**: 타입·단위 검사, 임시 PostgreSQL을 띄운 통합 테스트, 운영 이미지 빌드·권한 검사

## 현재
운영 중이며, 정량 성과·Scope 3·온실가스 관리 기능을 이어서 개발할 예정입니다. 고객사 시스템이라 저장소와 화면은 공개하지 않습니다.
